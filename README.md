# COBOTTA Natural Language Pick

自然言語で指定した物体をカメラ画像からGeminiで認識し、COBOTTAでピック＆プレースするWindows向けPythonアプリです。ブラウザの操作画面から、撮影・認識・座標確認・実機操作を行います。ROS 2は使用しません。

## 主な機能

- 「緑色の金魚を1個、その後に黒色の金魚を1個」など、自然言語による対象と順番の指定
- カメラ撮影からGeminiによる認識、座標変換、ピック＆プレースまでの自動実行
- 2指ハンドの閉方向に合わせた手先角度の計算
- 認識結果の座標一覧と画像マーカー表示（実行中・終了後も表示を保持）
- 撮影・認識・座標計算・実機ピックの個別操作
- JSON入力によるAPIを使用しない実行と、ロボットを動かさない模擬実行

## 動作環境

- Windows / Python 3.12
- COBOTTA（標準電動グリッパ、b-CAP通信）
- カメラ：Canon N10-W02
- Gemini APIキーとインターネット接続
- Git（リポジトリの取得に使用）

主な使用ライブラリはFlask、Waitress、NumPy、OpenCV、google-genaiです。依存関係とバージョン範囲は[requirements.txt](requirements.txt)を参照してください。b-CAP通信には同梱の`bcap.py`を使用します。

## セットアップ

### 1. リポジトリの取得とインストール

PowerShellで実行します。

```powershell
git clone https://github.com/SateetSpock/cobotta-natural-language-pick.git cobotta_pick
Set-Location cobotta_pick
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

非公開リポジトリの場合は、アクセス権のあるGitHubアカウントでの認証が必要です。

### 2. 接続設定

[config.json](config.json)を使用環境に合わせて設定します。

| 設定 | 初期値・内容 |
| --- | --- |
| `robot_ip` | `192.168.0.1` |
| `port` | `5007` |
| `camera_ip` | `192.168.0.90`（使用するカメラのIPに合わせて変更） |
| 画像サイズ | 1920 × 1080 |
| `robot_speed_percent` | ロボットの内部速度。設定値は操作画面にも表示 |
| 校正値 | 画像座標とロボット座標の対応点。詳細は「座標変換」を参照 |

PCの有線LANをロボットと同じサブネットに設定します。インターネット接続にはWi-Fiを使用します。コントローラー側ではb-CAPの読み書きとEthernet起動権を使用可能にしてください。

### 3. APIキー

Gemini APIキーは操作画面で入力するか、起動するPowerShellで環境変数を設定します。

```powershell
$env:GEMINI_API_KEY = "YOUR_API_KEY"
```

環境変数を設定した場合、画面のAPIキー欄は空欄で利用できます。`.env`の自動読込みには対応していません。APIキーをソースコードや`config.json`に記載しないでください。

## 起動

`app.py`があるフォルダーで実行します。

```powershell
.\.venv\Scripts\python.exe app.py
```

ブラウザで[http://127.0.0.1:8765](http://127.0.0.1:8765)を開きます。`start.cmd`でも起動できます。

終了する際は、ロボットの停止を確認してからターミナルで`Ctrl+C`を押します。

## 使い方

### 実機の準備

1. COBOTTAを自動モードにし、マシンロックを解除します。
2. 「接続・教示点を読む」でP10〜P15、現在位置、Tool/Work番号を読み取ります。
3. 画面のTool/Work番号を教示時の番号に合わせ、対象に応じた把持力を入力します。初期表示はTool=0、Work=0、把持力10 Nです。
4. 教示点と移動経路を確認し、画面の確認欄をチェックします。

「接続・教示点を読む」は読取りのみで、ロボットは動きません。読み取った教示点は`data/taught_points_日時.json`に保存されます。アプリはTool/Work番号の一致を確認し、現在の座標系を維持します。

### 自動実行

1. 「緑色の金魚を1個、その後に黒色の金魚を1個」などの指示を入力します。
2. 方式に「Gemini」を選びます。
3. 「スタート（撮影からピックまで）」を押します。

未接続の場合は自動接続し、次の順序で実行します。

**P10へ移動 → ハンド開放 → 撮影 → Gemini認識 → 座標変換 → 指定順にピック＆プレース → P10へ戻る**

認識後は確認待ちを挟まずにピックへ進みます。対象がない場合はP10で終了し、APIエラーや不正な座標の場合はピックを行いません。

### 個別操作

認識結果を確認してから動かす場合は、個別操作を使用します。

1. 「P10へ移動 → 開放 → 撮影」で画像を取得します。
2. 「個別操作：Geminiで候補だけ取得」で対象を認識します。
3. 画像マーカー、閉方向線、座標一覧を確認します。
4. 「表示順で実機ピック」を押します。

画像ファイルの読込み、撮影のみ、JSONからの座標計算、模擬実行も利用できます。「順番を模擬実行」はログの確認のみで、実機へ命令を送りません。

### JSON入力

Geminiを使わずに対象の位置と角度を指定する場合は、方式を「JSON」に切り替えます。

```json
{
  "targets": [
    {
      "label": "緑色の金魚",
      "point": [380, 645],
      "closing_angle_deg": 150
    }
  ]
}
```

| 項目 | 内容 |
| --- | --- |
| `label` | 対象名 |
| `point` | 画像上の`[x, y]`座標。各軸を0〜1000に正規化 |
| `closing_angle_deg` | ハンドの閉方向。画像の右向きを0°とし、時計回りの角度 |

単体オブジェクト、配列、`targets`で包んだ配列に対応します。JSON方式の「スタート」もP10への移動・開放・撮影から始まりますが、対象の再認識は行わず、入力した座標を使用します。

Geminiの認識結果もJSON欄に反映され、コピーできます。

## 教示点と動作順序

| 教示点 | 用途 | アプリによる書換え |
| --- | --- | --- |
| P10 | 撮影位置。校正時と同じ姿勢を使用 | なし |
| P11 | ピック位置への中継点 | なし |
| P12 | P13の40 mm上方 | あり |
| P13 | 対象のピック位置・姿勢 | あり |
| P14 | 投入先への中継点 | なし |
| P15 | 紙コップへの投入位置 | なし |

対象1個ごとに次の順序で動作します。

**P12/P13更新 → P11 → P12 → P13 → 把持 → P12 → P14 → P15 → 開放 → P10**

P12とP13の間は直線補間、それ以外はPTP移動です。各点への到達を確認して次へ進みます。P12/P13のFIGは接続時のP13から引き継ぎます。

把持は`HandMoveH`による力指定、開放は`HandMoveA`による30 mm・速度20%の指定です。把持確認が取れない場合は持上げを中止します。これらの命令に対応したコントローラー／プロバイダーを使用してください。

内部速度は`config.json`の設定を使用し、外部速度は変更しません。モーターは撮影・実行時にONとなり、終了時もONを維持します。

## 座標変換

画像とロボットの4点の対応から、平面ホモグラフィで画像座標をロボットのXY座標へ変換します。

| 校正点 | 画像座標 [x, y]（pixel） | ロボット座標 [X, Y]（mm） |
| --- | --- | --- |
| 1：右下 | [1243, 1025] | [133.85, -84.54] |
| 2：右上 | [1239, 152] | [244.56, -85.37] |
| 3：左下 | [335, 1029] | [135.22, 29.41] |
| 4：左上 | [331, 154] | [245.24, 28.31] |

同梱設定の画像座標は画像から読み取った値です。別の設置環境では対応点を設定し直してください。カメラ姿勢、レンズ設定、画像の切抜き・解像度、対象平面の高さを変更した場合も再校正が必要です。

| 項目 | 設定・計算方法 |
| --- | --- |
| X・Y | 平面ホモグラフィによる変換 |
| Z | 4.5 mm固定。対象物とTCPに合わせて設定 |
| Rx・Ry | Rx=179.47°、Ry=0.93° |
| Rz | 画像の閉方向を対象位置で座標変換し、水平時のRz=-174.40°を基準に計算 |

2指ハンドの180°対称性を利用し、Rzは`[-180, 180)`へ正規化します。レンズ歪み補正と3D姿勢推定は含みません。

## 動作上の仕様

- 認識は1回のスタートにつき1回です。複数対象のピック途中で再撮影・再認識は行いません。
- 実機実行には、撮影から5分以内、設定一致、現在位置がP10、教示点に変更がないことが必要です。
- 実行後・中断後の候補は再実行できません。次の実行には再撮影が必要です。
- 座標一覧と画像マーカーは実行中・終了後・中断後も表示され、次の撮影・画像読込み・認識などで更新されます。
- 把持失敗や通信エラーからの自動リトライ・自動復旧は行いません。

## 停止

画面の「停止要求」は、移動・ハンドの監視処理から`Robot_Halt`と`HandStop`を送信します。通信待ちや切断の影響を受けるため、実機の非常停止を代替するものではありません。

停止・通信エラー・把持失敗時は後続動作を中止し、自動開放や自動帰還は行いません。Geminiの応答待ち中に停止した場合は、戻ってきた結果を破棄します。

## データの扱い

Geminiには撮影画像と指示・出力形式のプロンプトを送信します。画面で入力したAPIキーはファイル・ログ・ブラウザ保存領域に保存せず、画面の再読込みで消えます。手入力のJSONも再読込み後には保持されません。

撮影画像・教示点を保存する`data/`、仮想環境、ログ、認証情報などはGitの管理対象外です。接続先・校正値・速度などのローカル設定は、更新時にも保持してください。

## V4の変更：把持条件と実寸基準を反映した候補選定

Geminiに送るプロンプトを`build_grasp_prompt()`へ分離し、設定値に応じた把持条件を毎回送信するようにしました。対象と順番だけの指示でも、次の条件を適用します。

- `config.json`の`open_mm`を今回の爪の開き幅として伝え、把持部分の幅と両側の余裕を考慮します。
- `image_points`と`robot_points`の対応を作業平面上の実寸基準として伝えます。画像サイズも`image_size`から反映します。
- 細長い物体は長い側面を挟み、長手方向に対して直角に閉じます。USBメモリは端子や穴、金魚模型は目玉やひれを避け、本体の安定した部分を選びます。

実寸情報はAIの候補選定の参考です。爪の厚み・長さや対象の高さは推定せず、数値による衝突判定は追加していません。座標変換、実機動作、速度設定、JSON直接入力の処理は従来どおりです。差分更新の手順は[README_UPDATE_v04.txt](README_UPDATE_v04.txt)を参照してください。
